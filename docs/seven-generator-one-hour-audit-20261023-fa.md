- مدل‌های تصویر و بازبینی تصویر جدا هستند؛ این اصلاح فقط درباره تولید متن است. سوابق قدیمی به دروغ با مدل 2.5 برچسب‌گذاری یا بازنویسی نشده‌اند.

## اقدام اصلاحی پیشنهادی بعد از این تشخیص

1. زمان‌بندی پنج مسیر متوقف‌شده با یک تغییر واقعی cron توسط حساب فعال دوباره ثبت و از دقیقه صفر پراکنده شود؛ سقف انتشار، توقف خانواده hose، کنترل اصالت، کیفیت و قفل جلوگیری از تکرار حفظ شوند. سپس شروع واقعی دو چرخه بعدی و نتیجه انتشار تک‌پستی بررسی شود.
2. برای رویا، موضوع‌های تازه و غیرتکراری با منابع تأییدشده تأمین شوند یا فقط شکست‌های مشخص و قابل اصلاح پس از بررسی جداگانه دوباره وارد صف شوند؛ بازکردن تولید hose یا آزادکردن همه شکست‌ها راهکار امنی نیست.
3. هشدار سلامت بر اساس آخرین اجرای واقعی و آخرین رسید انتشار باشد، نه فقط سبز بودن Actions.

GitHub رسماً مستند کرده که یک workflow زمان‌بندی‌شده ممکن است با وجود enabled بودن و کارکرد اجرای دستی، به علت وضعیت actor متوقف شود؛ تغییر cron توسط کاربر دارای دسترسی write یکی از روش‌های راه‌اندازی مجدد است. تأخیر/حذف در بار زیاد نیز مستند است. **این پایش، معلق/حذف‌شدن actor مشخصی را اثبات نکرده است**؛ علت قطعی فعلی در سطح مشاهده، نرسیدن schedule به شروع اجراست.

- دو خطای موقت خواندن workflow لوکس‌بلاگ بین نمونه‌ها ثبت شد؛ حالت ابتدا/انتها و پایش موازی بررسی شدند. داده گمشده به صفر انتشار تبدیل نشد.
- خطای HTTP 403 صفحه رزوبلاگ با مرورگر عمومی بررسی شد؛ عنوان و بدنه مقاله واقعاً بارگذاری شدند. بنابراین از این خطا قطعی سایت استنتاج نشد.
- API بدون احراز هویت محدود بود؛ داده اصلی از API فقط‌خواندنی داخل GitHub Actions جمع شد. توکن در خروجی یا فایل ثبت نشد.

- JSON تو‌در‌تو برای کنترل داده به ۹۱ ردیف نمونه×وبلاگ تبدیل شد؛ کلید ترکیبی یکتا است. تعدادهای تجمعی انتشار جمع زده نشده‌اند؛ اختلاف ابتدا/انتها با مجموعه شناسه‌ها و بررسی مستقیم مستقل تطبیق داده شد.
