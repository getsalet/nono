اتصال native REST با Application Password حساب اختصاصی `afp_agri_v2_bot`، شناسه ۲، نقش **author** انجام شده؛ نه administrator. مجوز انتشار نوشته‌های خود و رسانه تأیید شده است. Secrets:

- `AFP_WP_USERNAME`
- `AFP_WP_APP_PASSWORD`

مقادیر فقط داخل GitHub Actions خوانده می‌شوند؛ هرگز در کد، لاگ یا چت قرار نگیرند. رمز برنامه از مدیریت وردپرس قابل ابطال است. هاست، FTP و SQL مستقیم لازم نبوده و فعال نشده‌اند.

پایلوت `agri-af1a4b491d83`، «زمان مناسب برداشت لوبیا قرمز؛ نشانه‌های رسیدگی و معیار بازار»، نوشته 524163:

چرخه `40080964860` موفق بود: دریافت تازه موجودی ۱۱۸۸ نوشته عمومی، تولید متن، تولید سه WebP، ایجاد پیش‌نویس، آپلود و اتصال رسانه، انتشار یک نوشته، تأیید REST و HTTP عمومی. تصویر اول شاخص و دو تصویر داخل متن‌اند؛ هر سه تصویرسازی AI هستند، نه تصویر مستند مزرعه. رسیدها در `artifacts/agri-v2/new/agri-af1a4b491d83/` ثبت شده‌اند.

اجرای نخست `40080306530` به‌درستی روی HTML نامجاز متوقف شد؛ چیزی منتشر نکرد. قالب‌بندی بی‌خطر مدل نرمال شد، HTML فعال/اسکریپت/منبع تأییدنشده همچنان رد می‌شود. query فیلتر author در این سایت خطای ۵۰۰ داشت؛ حذف پارامتر با حفظ کنترل مالکیت محلی انجام شد، نه کاهش نقش یا دست‌کاری امنیت سایت.

پایلوت بعد از انتشار از نظر منابع و ویرایش بازبینی شد: خطای چندزبانه، جزئیات خارج از brief و متن مخصوص پیش‌نویس حذف؛ تصاویر خارج از فهرست‌ها قرار گرفتند. نسخه اصلاح‌شده و گزارش در مخزن همگام‌اند. **بازبینی AI مبتنی بر منابع با تأیید انسانی کارشناس کشاورزی یکسان نیست.** این محدودیت در مقاله و provenance آشکار است.

## اجرای خودکار محدود

`config.json` تولید خودکار و انتشار را برای **briefهای آماده و دارای اجازه انتشار** فعال می‌کند. سقف هر اجرا یک نوشته و بودجه تلاش هر موضوع دو چرخه است؛ اجرای ناموفق پیشرفت را نگه می‌دارد. اجرای هر ۵ دقیقه با cron `*/5 * * * *`، توسط `.github/workflows/afp-agri-v2-scheduled.yml` در main ثبت می‌شود؛ چون GitHub زمان‌بندی را فقط از شاخه پیش‌فرض می‌خواند. این فایل تنها router است: checkout و اجرای کد روی feature branch. گردش‌کارهای قدیمی دست‌نخورده‌اند.

در نبود brief آماده و منتشرنشده، scheduler بدون تماس مدل یا WordPress با `no_ready_unpublished_brief` تمام می‌شود. اجرای مجدد پایلوت تکمیل‌شده مقاله تکراری تولید نمی‌کند. این تنظیم به معنی تولید و انتشار جمعی همه ۲۹۰۵ عنوان نیست. برای توقف، `automatic_generation=false`؛ برای توقف همه مسیرهای cycle، `publication_enabled=false` کنید. توقف workflow زمان‌بندی نیز از رابط Actions ممکن است.

مسیر دستی محدود `.github/workflows/afp-agri-v2-live.yml` فقط با تغییر `data/agri-v2/live-request.json` روی همین feature branch یا dispatch عمل می‌کند؛ درخواست باید یک موضوع و `max_new_posts=1` و اجازه انتشار داشته باشد. فایل درخواست را برای تکرار نامحدود دست‌کاری نکنید. CI عمومی جدید تنها تست آفلاین اجرا می‌کند.

## قرارداد پژوهش و کنترل کیفیت

حالت معمول brief نیازمند دبیر و کارشناس واقعی، تاریخ، منابع با بخش/گزیده، طرح، حقایق و شرایط و بررسی معنایی است. برای منشأ REVIEW، `overlap_review_done=true` مستقل الزامی است؛ بررسی slug/عنوان جای بررسی معنایی را نمی‌گیرد.

استثنای شفاف پایلوت `ai_source_review_qualitative` است: حداقل دو منبع از دامنه‌های دانشگاهی بررسی‌شده MSU/WSU/ISU، بدون توصیه عددی، `human_agronomy_review_done=false` و `agronomy_reviewer=null`. نام یا تأیید متخصص جعل نشود. این استثنا مجوز تولید نسخه سم، کود، رطوبت هدف، تناژ یا تاریخ ثابت نیست. اعداد نوشته‌شده با حروف نیز نیازمند منبع و بررسی‌اند؛ کنترل لغوی ارقام صحت معنایی را ثابت نمی‌کند.

HTML محدود، allowlist منبع، طول و ارقام کنترل می‌شوند؛ کنترل انتشار متن چندزبانه ناخواسته و عبارت‌های مخصوص پیش‌نویس را متوقف می‌کند. هیچ‌کدام جای داوری علمی را نمی‌گیرد. خروجی خامِ ردشده صرفاً برای عیب‌یابی به‌عنوان داده JSON نگه داشته می‌شود، نه HTML قابل اجرا. برای ادعاهای حساس، تولید متوقف و تأیید متخصص گرفته شود.

## نگهداری پیشرفت و مالکیت

فایل‌های متن/تصویر/رسید قبل از ادامه ثبت می‌شوند. تغییر brief پس از staging خطاست. تصویر ساخته‌شده دوباره فراخوانی نمی‌شود. پیش از هر مدل، موجودی تازه عمومی دریافت می‌شود؛ خطا یا موجودی خالی fail-closed است. نقش author به پیش‌نویس خصوصی سایر نویسندگان دسترسی ندارد؛ این موجودی را ممیزی کامل محتوای خصوصی معرفی نکنید.

نوشته‌ها با slug و marker اختصاصی reconcile می‌شوند؛ ویرایش فقط برای نوشته دارای مالکیت حساب فنی و marker همان موضوع مجاز است. رسانه موجود نیز باید متعلق به حساب فنی و همان نوشته یا بدون اتصال باشد. رسید نهایی موفق مانع بازتولید است. خطای شبکه پس از POST ابتدا با بررسی وضعیت واقعی حل شود، نه POST کور. سقف تلاش را بدون بررسی افزایش ندهید.

## تست و استفاده آفلاین

Python 3.12 و Pillow:

```sh
python -m pip install pillow
python -m unittest discover -s tests/agri_v2 -v
python -m automation.agri_v2 validate
```

۴۷ تست آفلاین شامل تمامیت داده، کنترل منابع/HTML/عدد، سلامت و دامنه کلید، نقش و مالکیت وردپرس، قالب تصاویر و محدودیت انتشار در محیط آماده‌سازی پاس شده‌اند. validate هیچ مدل یا سایت را تغییر نمی‌دهد و وضعیت تنظیمات را گزارش می‌کند. CLI `draft` همچنان فقط artifact پیش‌نویس می‌سازد؛ CLI `merge-plan` فقط پیشنهاد ادغام با قفل هش/نسخه می‌دهد، نه اعمال زنده.

فقط تیپ بغل‌دوخت AFP با روزنه ۱۰ و ۲۰ سانتی‌متر: فشار کاری **۰٫۶ تا ۱ اتمسفر (atm)**، نه bar یا فشار آزمون. شرایط مرجع دبی تأیید نشده و از این فشار، دبی یا طول خط نتیجه‌گیری نشود. ترجمه پنج‌زبان و اتصال حقایق به چت‌بات در این مرحله اجرا نشده‌اند.


## اصلاح قالب تصویر، جدول و FAQ

طبق درخواست جدید مالک، کپشن تکراری زیر تصاویر حذف شده و caption رسانه‌های جدید خالی است. برچسب قطعی `AFP | 09134922013` با Pillow در پایین راست اضافه می‌شود؛ متن تلفن به مدل تصویر سپرده نمی‌شود. مرجع واقعی بسته‌بندی تیپ و قواعد هویت محصول از `aghala2` در commit `78bfca407addcff53a4a49777a4c467f15051d3a` اقتباس شده‌اند. تصویر مرجع در `automation/agri_v2/assets/afp-tape.webp.b64` است و همراه درخواست مدل ارسال می‌شود؛ سه نقش تصویری متفاوت، محصول ثانویه در پایین چپ و ممنوعیت افراد/بسته‌بندی اضافه حفظ شده‌اند. این بسته در گرافیک‌ها تصویرسازی است، نه سند عملکرد محصول.

هر مقاله اکنون باید جدول تصمیم/مقایسه مبتنی بر حقایق مصوب و دقیقاً سه FAQ در فیلد جداگانه داشته باشد. پرسش‌ها با همان `faq-section` و `details/summary` مشاهده‌شده در صفحه اصلی سایت رندر می‌شوند و در انتهای مقاله قرار می‌گیرند. محتوای FAQ نیز از نظر ارقام با حقایق مصوب کنترل می‌شود؛ جدول مجوز ساختن عدد نیست. FAQ از متن آزاد مدل HTML اجرایی دریافت نمی‌کند؛ renderer قطعی و escape‌شده است. داده ساختاریافته باید پس از اعمال زنده بررسی شود و وعده نمایش rich result وجود ندارد.

۴۷ تست آفلاین پاس شده‌اند. گردش‌کار اصلاح یک نوشته `afp-agri-v2-style-revision.yml` برای اصلاح همان پایلوت افزوده شده؛ نوشته تازه ایجاد نمی‌کند، سه تصویر را resumable بازسازی می‌کند و مالکیت و تغییر نسخه نوشته را پیش از اعمال کنترل می‌کند. در اجراهای `40084726687` و `40084923871` قبل از هر درخواست تصویر متوقف شد: نوشته 524163 اکنون `trash` است؛ مالک حساب فنی و marker صحیح‌اند، اما URL قبلی 404 می‌دهد. علت یا عامل انتقال به زباله‌دان مشخص نیست. هیچ بازگردانی/انتشار دوباره یا مقاله جایگزینی انجام نشده است. اعمال زنده این اصلاحات و بازسازی تصاویر منتظر تصمیم مالک برای بازگردانی همان نوشته است.
