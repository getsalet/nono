# هماهنگ‌کننده محدود کارگر تصویر AFP

هدف: کم‌کردن وابستگی هر درخواست تصویر به cron غیرقطعی GitHub Actions. این تغییر، ظرفیت یا زمان پاسخ Agnes را تضمین نمی‌کند و اثبات تحقق سه انتشار در نیم‌ساعت نیست.

## رفتار اجرایی

- یک workflow مستقل، با قفل مخصوص و بدون قطع اجرای قبلی، در هر نوبت حداکثر ۵۵ دقیقه فعال می‌ماند. برنامهٔ نیم‌ساعته برای ادامهٔ پوشش وجود دارد؛ تأخیر شروع runner یا cron همچنان ممکن است.
- هر ۶۰ ثانیه آخرین کنترل‌ها، صف مقاله‌ها، وضعیت مسیرهای ممیزی‌شده و سابقهٔ اجرای همان کارگر را می‌خواند.
- فقط اگر مقاله‌ای با خانواده نوار تیپ مجاز منتظر باشد، کارگر دیگری فعال نباشد و زمان‌های retry/cooldown گذشته باشند، workflow موجود `blog-image-stock.yml` را روی main درخواست می‌کند.
- فاصلهٔ درخواست‌ها حداقل پنج دقیقه است؛ با وجود ۱۲ اجرای کارگر در ساعت شناور، درخواست تازه صادر نمی‌کند. این سقف، تصمیم هماهنگ‌کننده بر اساس سابقهٔ قابل مشاهده است؛ رزرو سخت و اتمیک همهٔ رویدادهای هم‌زمان GitHub نیست. قفل و فاصلهٔ سراسری خود کارگر همچنان مرجع قطعی شروع درخواست تصویرند.
- سقف هر نشست ۱۲ درخواست اجرای کارگر است. پذیرش dispatch به‌معنای شروع یا موفقیت کارگر نیست. درخواست پذیرفته‌شده باید در سابقه دیده شود؛ اگر تأیید آن نامعلوم بماند، نشست متوقف می‌شود و درخواست کور تکرار نمی‌شود.
- خرابی ممیزی، دادهٔ ناقص، خطای مشاهده، توقف کاربر، انقضای ممیزی، محدودیت حساب و شکست اجرای کارگر اجازهٔ دورزدن محافظ‌ها را نمی‌دهند. خطای ۴۲۹/سهمیه موجب تعویض مسیر برای فرار از محدودیت نمی‌شود.

## محدودیت‌های حفظ‌شده

هماهنگ‌کننده هیچ کلید Agnes دریافت نمی‌کند؛ فقط توکن محدود Actions برای خواندن و درخواست اجرای workflow دارد. هیچ API تصویر، متن یا انتشار بومی را فراخوانی نمی‌کند. کارگر اصلی همچنان حداکثر یک درخواست تصویر در هر اجرای خود، mutex سراسری، فاصلهٔ حداقل ۶۰ ثانیه، وقفه‌های مسیر و سرویس، موجودی حداکثر ۱۲، سهم سه تصویر برای هر وبلاگ و کنترل کیفیت حداقل ۹۰ را حفظ می‌کند. بلاگفا بازنشسته و لوله نخی خارج از تولید می‌مانند.

خطای بیرونی ۵۰۳ یا نبود تصویر مناسب با این تغییر «حل‌شده» محسوب نمی‌شود. امتیازها و نتیجهٔ قبلی ارزیابی‌ها تغییر نمی‌کنند؛ تصویر ناقص برای پرکردن آمار منتشر نمی‌شود. گزارش واقعی انتشار همچنان جداگانه و از رسید ناشر محاسبه می‌شود.

شواهد هر نشست در artifact مستقل `afp-image-coordinator-…` ذخیره می‌شود. برای توقف، کنترل `enabled` هماهنگ‌کننده یا توقف سراسری تولید قابل استفاده است؛ بررسی هر دو در حین نشست تکرار می‌شود.
