# رفع تداخل تعویق سرویس تصویر با ذخیره‌سازی نتایج

در پایش یک‌ساعتهٔ `38940980056`، مراحل ذخیرهٔ checkpoint رز‌بلاگ و بلاگفا نیز شکست داشتند. بررسی کد یک ایراد جانبی در اصلاح قبلی تعویق صف را نشان داد: `defer()` فایل tracked مشترک را در checkout زنده تغییر می‌داد، درحالی‌که commit جداگانه فقط نسخهٔ remote را ثبت می‌کرد. گارد workflow در برابر تغییر tracked خارج از مسیرهای مجاز، سپس می‌توانست checkpoint عادی وبلاگ را متوقف کند.

این تداخل در یک مخزن آزمایشی مستقل با همان الگوی نوشتن، بدون API یا انتشار، بازتولید شد. آزمون جدید پیش از اصلاح شکست خورد و پس از اصلاح پاس شد. این شواهد علت تمام شکست‌های اجرای واقعی را اثبات نمی‌کند؛ مرحلهٔ تولید تصویر نیز جداگانه می‌تواند شکست بخورد.

اکنون cache محلیِ زمان اجرا در `artifacts/blog-image-runtime/provider-cooldown.json` قرار می‌گیرد. فایل مشترک `data/blog-image-provider-backpressure.json` فقط از طریق index جداگانه در remote ثبت می‌شود و checkout زنده دست‌نخورده می‌ماند. خواندن زمان تعویق، بیشینهٔ نسخهٔ مشترک، cache محلی و نسخهٔ remote را لحاظ می‌کند. شکست checkpoint شبکه نیز cache محلی را از بین نمی‌برد.

۳۴۳ آزمون محلی پاس شدند؛ از جمله حفظ بایت‌های فایل tracked، حفظ تغییرات نامرتبط، و باقی‌ماندن تعویق محلی پس از خطای ذخیرهٔ remote. workflow جدید فقط آزمون آفلاین دارد؛ هیچ درخواست تصویر، ورود، انتشار یا تغییر مجوز انتشار انجام نمی‌دهد.

پایش جاری از نو شروع نشد و کنترل انتشار لوله نخی باز نشد. اعتبارسنجی اجرای واقعیِ checkpoint پس از این اصلاح باید جدا از موفقیت آزمون‌ها گزارش شود.
