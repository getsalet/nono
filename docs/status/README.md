# پنل وضعیت وبلاگ‌ها

نشانی: https://getsalet.github.io/nono/status/

## برگه‌ها
- نمای کلی هفت وبلاگ، زمان آخرین انتشار و آمار ثبت‌شده.
- صفحه مستقل هر وبلاگ: رسیدها، صف، موانع کیفی، اجراها، زمان‌بندی و منابع.
- آرشیو انتشارها با جست‌وجو، فیلتر، صفحه‌بندی و خروجی CSV.
- وضعیت مخزن: آخرین commitها، نمونه ۱۰۰ اجرای اخیر، خطاهای دسترسی به منابع.
- راهنما و توضیح محدودیت شمارش.

## تعریف و تازگی داده
آمار تعداد پست‌ها از رسیدهای یکتای مخزن است، نه شمارنده تمام مطالب عمومی یا آمار بازدید. زمان انتشار از رسید می‌آید؛ وبلاگ‌ها هنگام نمایش پنل مستقیماً وارسی نمی‌شوند. شماره آخرین پست تعداد کل فرض نمی‌شود. بازیابی با زمان اولیه نامشخص در آمار ۲۴ ساعت/۷ روز وارد نمی‌شود. داده ناموجود، نامشخص است نه صفر.

پنل رسیدهای فعلی را همچنان از SHA ثابت مخزن می‌خواند؛ fallback به main صریح گزارش می‌شود. عنوان‌ها و آخرین اجرای هر workflow از یک فایل عمومی سبک در شاخهٔ `status-data` دریافت می‌شوند. این فایل فقط عنوان، شناسه، نشانی، زمان رسید و فیلدهای مجاز اجرای هر workflow را دارد؛ متن مقاله، prompt، تصاویر، خطاهای خام یا credential در آن قرار نمی‌گیرد.

گردش‌کار `status-public-data.yml` فایل را پس از پایان workflowهای هشت‌گانه، هر پنج دقیقه و هنگام تغییر سازنده به‌روز می‌کند. این زمان‌بندی تضمین اجرای دقیق GitHub نیست؛ snapshot قدیمی‌تر از ۱۵ دقیقه یا دارای زمان آینده نامعتبر مصرف نمی‌شود. منبع اصلی همه فایل‌ها `main` است؛ خروجی فقط در `status-data/status-snapshot.json` نوشته می‌شود و main یا صف انتشار را تغییر نمی‌دهد.

با snapshot معتبر، بازکردن آرشیو نیازی به دریافت هفت فایل بزرگ صف ندارد. صف فقط برای جزئیات همان وبلاگ، رسید جدیدی که هنوز در شاخص نیست، یا جایگزینی شاخص نامعتبر/قدیمی خوانده می‌شود. عنوان ناموجود حدس زده نمی‌شود؛ وضعیت پوشش جست‌وجو و CSV همچنان صریح است. عنوان شاخص با کلید و نشانی متعارف همان رسید تطبیق داده می‌شود؛ زمان و تعداد انتشار همیشه از رسیدهای فعلی می‌آید، نه snapshot.

وضعیت هر وبلاگ از درخواست مستقل آخرین اجرای workflow خودش و در مورد رویا از هر دو workflow تولید و انتشار می‌آید، نه نمونهٔ آخرین ۱۰۰ اجرای مخزن. اگر مشاهدهٔ مستقل در snapshot موجود نباشد، مرورگر endpoint همان workflow را جدا می‌خواند. موفقیت نمونهٔ مخزن جایگزین شکست این دریافت نمی‌شود. برای کنترل سهمیهٔ API عمومی، پاسخ معتبر جایگزین حداکثر ۱۵ دقیقه کش و شکست دریافت پنج دقیقه cooldown دارد؛ زمان مشاهدهٔ مستقل اجرا روی صفحه دیده می‌شود. دریافت‌های مرورگر همچنان حداکثر شش درخواست هم‌زمان دارند. نمونهٔ ۱۰۰ اجرای کل مخزن فقط در صفحهٔ زیرساخت استفاده می‌شود.

ساعت نسبی هر ۳۰ ثانیه و داده‌ها هر پنج دقیقه در صفحه قابل‌مشاهده تازه می‌شوند. محدودیت API، خطای شبکه و داده قبلی پنهان نمی‌شوند. توکن یا credential در مرورگر درخواست/ذخیره نمی‌شود؛ توکن کوتاه‌عمر Actions فقط سمت GitHub برای ساخت snapshot استفاده می‌شود.

بلاگفا بازنشسته است و درخواست پایش برای آن ارسال نمی‌شود. این پنل فقط خواندنی است؛ مدل‌ها، زمان‌بندی و کنترل کیفیت تولید را تغییر نمی‌دهد.

## آزمون و استقرار
```sh
node --test tests/status_data.test.cjs tests/status_repair.test.cjs tests/status_priorities.test.cjs tests/status_font.test.cjs tests/status_snapshot.test.cjs
```
۷۹ آزمون قرارداد داده و استقرار، شامل آزمون‌های مستقل تازگی انتشار/وضعیت اجرا، جمع داده قدیمی و ناموجود، پوشش زمانی و یکسانی فیلتر جست‌وجو/CSV.

آزمون اختیاری مرورگر با Playwright و Chromium:
```sh
# به Playwright و مرورگر نصب‌شده نیاز دارد؛ مسیر مرورگر قابل تنظیم است.
CHROMIUM_PATH=/path/to/chromium node tests/status_priorities.browser.cjs
CHROMIUM_PATH=/path/to/chromium node tests/status_snapshot.browser.cjs
```
تمام پاسخ‌های API و فایل‌های عمومی در این آزمون کنترل‌شده‌اند؛ هیچ انتشار یا تغییر مخزن انجام نمی‌شود. آزمون‌ها هر دو مسیر snapshot سالم و نبود آن، عدم دریافت هفت صف در مسیر اصلی، جست‌وجو/CSV، دریافت هدفمند رسید جدید، جزئیات تنبل صف، شکست جزئی API مستقل، کش سهمیه، هشدار عنوان ناقص و نمایش موبایل ۳۹۰ پیکسل را بررسی می‌کنند. این آزمون جایگزین تأیید استقرار زنده نیست.

## سه وضعیت مستقل و پوشش آمار
- نتیجه workflow، تازگی آخرین انتشار ثبت‌شده و کیفیت داده جدا نمایش داده می‌شوند؛ اجرای جاری یا توقف عمدی هشدار انتشار قدیمی را نمی‌پوشاند.
- دریافت موفق فایل، اثبات انتشار تازه یا سلامت زنده وبلاگ نیست. زمان آخرین دریافت موفق رسید هر وبلاگ نمایش داده می‌شود.
- اگر مجموع از داده قبلی استفاده کند، تعداد وبلاگ‌های با داده قدیمی کنار همان کارت ذکر می‌شود. منبع ناموجود همچنان نامشخص است؛ مجموع ناقص با ≥ مشخص می‌شود.
- تعداد رسید دارای زمان معتبر و بدون زمان معتبر در نمای کلی و جزئیات وبلاگ نمایش داده می‌شود. رسیدهای بدون زمان معتبر در بازه ۲۴ ساعت/۷ روز شمرده نمی‌شوند.

گردش‌کار `afp-agri-v2-dashboard.yml` ابتدا آزمون‌ها را اجرا و سپس تمام فایل‌های این پوشه را کنار داشبورد کشاورزی موجود منتشر می‌کند.

## فونت فارسی
فونت رابط، عنوان‌ها، کنترل‌ها و اعداد **وزیر (Vazir v30.1.0)** است و از `fonts/vazir.css` در همین سایت ارائه می‌شود. فونت در CSS تعبیه شده و به CDN یا نصب محلی وابسته نیست؛ `font-display: swap` فعال است. شناسه‌ها و کدها monospace باقی می‌مانند. مجوز کامل و مشخصات منبع در پوشه `fonts/` نگهداری می‌شود.

## ساخت دستی شاخص عمومی
```sh
node automation/build_status_snapshot.cjs --root . --revision "$(git rev-parse HEAD)" --output /tmp/status-snapshot.json
```
سازنده باید به فایل‌های رسید و صف هفت وبلاگ دسترسی داشته باشد؛ فقدان منبع، ساخت عنوان‌ها را متوقف می‌کند تا خروجی ناقص به‌عنوان کامل منتشر نشود. خطای API یک workflow جداگانه ثبت می‌شود و سایر داده‌ها را با موفقیت ساختگی جایگزین نمی‌کند. شاخهٔ عمومی `status-data` مقصد اختصاصی سازنده است؛ برای فعال‌شدن workflow باید این شاخه از قبل وجود داشته باشد.

ماتریس عنوان نیلوبلاگ از آرایه `titles` و شناسه `id` خوانده می‌شود؛ این آرایه با کلید دقیق رسید تطبیق دارد و خالی‌بودن `items` به‌عنوان نبود عنوان یا خالی‌بودن صف تعبیر نمی‌شود.
