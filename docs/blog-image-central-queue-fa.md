# صف مرکزی تصویر پنج وبلاگ

## دامنه

همین مخزن nono هماهنگ‌کننده است؛ مخزن تازه ساخته نشده است. فقط تولید تصویر جدید قفل می‌شود، نه خواندن تصویر موفق کش‌شده، کنترل کیفیت، متن یا انتشار پست آماده. دامنهٔ فعال همچنان نوار تیپ است؛ تولید لوله نخی و آزمون‌های تصویر آن لغوشده باقی می‌مانند. روش تصویر وابسته به موضوع، مرجع واقعی محصول، واترمارک AFP | 09134922013 و کنترل‌های پیش از انتشار تغییر نکرده‌اند.

## هماهنگی میان اجراگرها

هر درخواست آمادهٔ تولید در GitHub یک بلیت موقت FIFO می‌گیرد. کلید مقاله فقط شناسهٔ هش‌شده است؛ کلید API، متن مقاله، پرامپت و پاسخ سرویس در بلیت ذخیره نمی‌شود. فقط سر صف می‌تواند برای ساخت ref ثابت afp-blog-image-provider-lock-v1 تلاش کند. ساخت ref در GitHub اتمی است؛ در حالت عادی فقط یک مالک برنده می‌شود. refها خارج از main هستند و فایل‌های اصلی مخزن را تغییر نمی‌دهند.

قفل از درست پیش از درخواست تولید تا دریافت و پردازش پاسخ نگه داشته می‌شود؛ تلاش‌های مجدد همان درخواست نیز داخل همان قفل هستند. پس از تملک، وضعیت تازهٔ توقف مشترک از main خوانده می‌شود. فاصلهٔ شروع نوبت‌های جدید حداقل ۶۰ ثانیه است. انتظار بلیت عادی ۱۸۰ ثانیه به‌اضافه سربار محدود دسترسی شبکه است؛ پس از آن پیش‌نویس ذخیره و برای تلاش بعدی عقب می‌افتد. صف محتوای هر وبلاگ منبع ماندگار کار است؛ بلیتِ انتظار، دائمی نیست.

## خطای ظرفیت

در پاسخ صریح image_queue_full، قبل از آزادسازی قفل، توقف مشترک ثبت می‌شود. شکست‌های متوالی در بازهٔ یک‌ساعته فاصلهٔ تلاش را به ۵، ۱۰، ۲۰ و حداکثر ۳۰ دقیقه می‌رسانند؛ Retry-After طولانی‌تر رعایت می‌شود. فقط دریافت واقعی تصویر موفق، شمارنده را بازنشانی می‌کند؛ سبزشدن workflow یا آزمون قفل شاهد بازیابی سرویس نیست.

## شکست و پاکسازی

مالک فعال، حتی پس از گذشت زمان طولانی، کنار زده نمی‌شود. بلیت مالکِ قطعاً پایان‌یافته قابل پاکسازی است. قفل رهاشده فقط پس از تأیید پایان اجرای مالک و ۳۰ دقیقه قرنطینه قابل بازیابی است. مالک نامعلوم، وضعیت ناخوانا، دسترسی ناکافی و نتیجهٔ مبهم API باعث توقف بدون درخواست تصویر می‌شود. در ناموفق‌بودن ثبت توقف مشترک، قفل حفظ می‌شود تا runner بعدی بی‌اطلاع درخواست تازه نفرستد. قفل با ریست‌کردن اجباری، حذف تصادفی ref یا تغییر کلید API دور زده نمی‌شود.

این طرح هماهنگی درخواست‌های پنج وبلاگ را اصلاح می‌کند؛ ظرفیت سرویس بیرونی را افزایش نمی‌دهد و مدت پردازش احتمالی در سمت سرویس پس از timeout را تضمین نمی‌کند.

## آزمون عملی

workflow blog-image-queue-check دو runner واقعی را برای گرفتن همین قفل مشترک به رقابت می‌گذارد. هر runner فقط ۸ ثانیه داخل قفل می‌ماند؛ هیچ کلید سرویس تصویر دریافت نمی‌کند و هیچ تصویر یا پستی تولید نمی‌کند. گزارش فقط عدم هم‌پوشانی نوبت‌ها، مالکیت ثابت و پاکسازی عادی بلیت‌ها را می‌آزماید. نتیجهٔ واقعی آزمون در artifacts/blog-image-queue-check ذخیره می‌شود.

## نتیجهٔ آزمون میزبانی‌شده

در اجرای https://github.com/getsalet/nono/actions/runs/38965792025 تمام آزمون‌ها و هر دو probe و اعتبارسنج نهایی موفق شدند. دو runner واقعی قفل مشترک عملیاتی را به نوبت گرفتند، مالکیت در زمان نگه‌داشتن ثابت بود و بازه‌های بحرانی هم‌پوشانی نداشتند. بلیت هر probe پس از خروج پاک شد. هیچ درخواست تصویر و هیچ ارسال پست در این آزمون انجام نشد.

۳۶۹ آزمون محلی با محیط شبیه‌سازی‌شدهٔ GitHub Actions نیز گذشت. اتصال گارد به مرحلهٔ تولید هر پنج workflow در آزمون‌ها کنترل شد. اجراهای push فارسی‌بلاگ، روزبلاگ، بلاگفا و لوکس‌بلاگ برای این تغییر سبز بودند، اما این اجراهای push فقط آزمون هستند و شاهد انتشار یا تولید تصویر تازه نیستند.

گزارش اثبات: artifacts/blog-image-queue-check/38965792025.json. قفل و فاصله‌گذاری فعال شده‌اند؛ بازیابی ظرفیت سرویس بیرونی و انتشار تازه هنوز با این آزمون تأیید نشده است. زمان‌بندی‌های پنج وبلاگ حفظ شدند و دامنه همچنان فقط tape20 است.
